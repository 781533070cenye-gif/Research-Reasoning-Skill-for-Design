# Modes and workflow

Use this reference when the task depends on stage selection, transition timing, research architecture, or freeze decisions.

## Mode routing

Infer mode from both language and project evidence. The latest explicit user instruction overrides inference.

| Signal | Route | Required move |
| --- | --- | --- |
| “我突然想到…” / “会不会还可以…” | `EXPLORE` | Expand possible explanations and label uncertainty. |
| “有没有人研究过？” | `EXPLORE` or `CRYSTALLIZE` | Run literature positioning and novelty-threat search, not topic accumulation. |
| “这能不能成为研究？” | `CRYSTALLIZE` | Extract phenomenon, assumption, tension, unknown, and researchable version. |
| “我到底研究的是什么？” | `CRYSTALLIZE` | Compare candidate problem statements and exclusions. |
| “准备做实验/问卷/访谈” | `CRYSTALLIZE` | Build an RQ–Evidence map before instrument design. |
| “数据出来了” | `EVIDENCE` | Inspect structure, anomalies, cases, and visuals before drafting Results. |
| “结果显著” | `EVIDENCE` | Ask what substantive pattern the result reveals and how large or stable it is. |
| “是不是可以说明…” | `EVIDENCE` | Run claim–evidence and level checks. |
| “两个 Study 怎么合？” | `EVIDENCE` or `CONVERGE` | Identify shared theoretical problem and complementary evidence roles. |
| “现在要定主线” | `CONVERGE` | Rank claims, cut or park branches, and state the argument spine. |
| “准备投稿了” | `CONVERGE` | Apply freeze protocol and submission QA. |

If the user is revisiting settled work, preserve the current mode unless they explicitly reopen it. Do not let a fresh but peripheral idea pull a converging project back into exploration; park it first.

## Research workflow

Use only the phases needed by the request.

### A. Phenomenon discovery

Convert an intuition into:

`observed phenomenon → anomaly → possible tension`

Ask what specifically happened, where, to whom or what, and relative to which expectation. Avoid naming a topic as if it were a phenomenon.

### B. Divergent exploration

Generate multiple categories of explanation: historical, institutional, cultural, behavioral, spatial, informational, technological, economic, and design-based where relevant. Mark each item as `hypothesis`, `analogy`, `possible mechanism`, `counterexample`, or `literature lead`.

### C. Problem crystallization

Answer:

1. What is not understood?
2. How is it usually explained or designed around?
3. Which assumption would change if the observation holds?

Produce a tension statement before producing a title.

### D. Literature positioning

Search and organize by function. Locate the closest conceptual and empirical precedent, including work using different vocabulary. Record direct novelty threats. A defensible gap may be an untested relation, missing temporal process, inappropriate unit of analysis, unexamined default assumption, or weak translation from evidence to design—not only an absent topic.

### E. Concept formation

Prefer an established construct when it captures the phenomenon. Create a working construct only when it differentiates observations that existing terms collapse. Define its referent, contrast class, boundary, and evidence level.

### F. Research architecture

Build in this order:

`RQ → knowledge needed → evidence type → unit of analysis → method → possible claim`

Check that each study has a distinct evidential role and that the full set is necessary. Do not add a method to make a project look mixed-method.

### G. Operationalization

Map:

`construct → observable trace → coding or measurement rule → derived variable → analytic comparison`

Specify inclusion, exclusion, ambiguity, missingness, repeated observations, and versioning. Distinguish behavioral traces, self-report, researcher interpretation, and measured outcomes.

### H. Analysis as discovery

Triangulate aggregate analysis, visualization, and case inspection. Examine expected patterns, violations, local patterns hidden by averages, within-person versus between-person variation, sensitivity to definitions, and alternative explanations.

### I. Finding extraction

Organize Results by findings, not analysis commands. A finding states a structure in the phenomenon, supported by analyses. When possible, retain 3–4 findings that are necessary, distinct, and jointly sufficient for the main argument.

### J. Claim–evidence locking

For every central claim record:

`claim → direct evidence → supporting evidence → figure/table → allowed inference → prohibited inference`

After locking, add a core claim only if new evidence requires it or an existing chain fails.

### K. Multi-study synthesis

For each study state its question, evidence type, scale, finding, limitation, and contribution to the shared argument. Use `complements`, `extends`, `qualifies`, or `shows at another scale` unless the design truly supports `validates` or `confirms`.

### L. Contribution abstraction

Move upward in order:

1. Empirical: previously unknown pattern.
2. Analytical: unit, comparison, or temporal/spatial scale that must change.
3. Conceptual: revised understanding or construct.
4. Design/HCI: changed assumption and resulting design capacity.

Do not start with a desired contribution and backfill evidence.

### M. Evidence audit

Tag central statements as `Observed`, `Inferred`, `Proposed`, or `Speculative`. Revise verbs and scope to match the tag. Preserve useful speculation by marking it, not deleting it automatically.

### N. Freeze protocol

Use freezes progressively:

| Freeze | What stops | What may continue |
| --- | --- | --- |
| Analytical | New main analyses | Error correction, predeclared robustness, necessary verification |
| Conceptual | New constructs and central claims | Sharpening definitions and boundaries |
| Content | Structural rewrites and new sections | Local clarity, citation, and consistency edits |
| Submission | Content edits | Format, metadata, accessibility, upload, and final checks |

If a post-freeze issue threatens validity, explicitly reopen the narrowest affected layer and record why.
